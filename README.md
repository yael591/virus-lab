# חילוץ התחייבויות: המעבדה המרכזית לנגיפים

מערכת שקוראת טפסי התחייבות (סרוקים, מצולמים או כתובים ביד) ויוצרת רשומה לכל מספר התחייבות.
כל רשומה כוללת שם פרטי, שם משפחה, ת.ז., גורם שולח, מספרים מרכזיים ותאריך קבלה.
המערכת מסמנת בכתום כל שדה שהיא לא בטוחה בו, והלבורנטית מתקנת ומאשרת.

## איך זה עובד

```
העלאה (PDF / תמונות)
  → פיצול לעמודים ורינדור (בדפדפן)
  → OCR בעברית ואנגלית עם מיקומי מילים, ותיקון סיבוב אוטומטי (Tesseract, בדפדפן)
  → שמירת התמונה ב-Storage פרטי
  → Edge Function "extract":
       רג'קס לפי גורם שולח → Claude (תמונה + טקסט OCR + רמזי הרג'קס) → JSON
       → פענוח עמיד → נרמול → אימות מול טקסט הדף → תיקון ת.ז. לפי ראיות → סימון ביטחון
  → forms (פרטי מטופל ודגימה) + records (שורה לכל התחייבות)
  → מסך בדיקה: תאים כתומים, חיתוך מהטופס בריחוף, תיקון במקום, אישור
```

**שכבות הבקרה סביב המודל**

| שכבה | קובץ | מה היא עושה |
|---|---|---|
| רג'קס לפני המודל | `engine/regex-profiles.ts` | מוצא מספרים בטקסט מודפס ומעביר אותם למודל כרמז. בהמשך מתריע על מספר שהמודל פספס |
| פענוח עמיד | `engine/parse.ts` | מציל תשובה שנחתכה, ומוסיף אזהרה |
| אימות מול הדף | `engine/verify.ts` | ערך או ציטוט שלא מופיעים בטקסט הדף, כשהביטחון נמוך מ-0.9, מסומנים לבדיקה |
| תיקון ת.ז. לפי ראיות | `engine/normalize.ts` | מתקן רק כשבדף מופיע מספר תקין ששונה מהערך של המודל בספרה אחת. בלי ריפוד |
| עיגון למיקום | `engine/anchor.ts` | מחפש את הערך בין מילות ה-OCR ומחזיר תיבה על העמוד. אם הערך לא נמצא, לא מומצא מיקום |

`engine/` = `supabase/functions/_shared/engine/`. זה קוד TypeScript טהור, שרץ גם בדפדפן וגם ב-Edge Function.

**כללים קבועים**
- שדה שלא נמצא נשאר ריק ומסומן. לא מנחשים.
- גורם שולח נבחר רק מהרשימה הסגורה (טבלת `senders`).
- רשומה שאושרה לא משתנה בהרצה חוזרת (בדיקה ב-Edge Function, וגם trigger במסד הנתונים).
- פרטיות: ה-OCR רץ בדפדפן. השירות החיצוני היחיד הוא מודל השפה, שמקבל רק את תמונת העמוד ואת הטקסט שלו.
  כפתור "מחיקת מקורות" מוחק תמונות וטקסט OCR של טפסים שאושרו במלואם.

## התקנה (כ-20 דקות)

**שלב 1: Supabase**
1. יוצרים פרויקט חדש ב-supabase.com.
2. ב-Authentication → Users → Add user יוצרים משתמש למעבדה (אימייל וסיסמה).

**שלב 2: מסד נתונים ופונקציה**
```bash
npm install
npx supabase init            # אם נשאלים שאלות, עונים No
npx supabase login
npx supabase link --project-ref <PROJECT_REF>
npx supabase db push         # טבלאות, RLS, bucket, רשימת גורמים שולחים
npx supabase secrets set ANTHROPIC_API_KEY=<המפתח>
# אופציונלי:
# npx supabase secrets set ANTHROPIC_MODEL=claude-sonnet-5-5
# npx supabase secrets set STRICT_ID_CHECKSUM=true   # ת.ז. עם ספרת ביקורת שגויה תסומן בכתום (בדוגמאות הת.ז. שונו, לכן ברירת המחדל היא רק אזהרה)
npx supabase functions deploy extract
```

**שלב 3: האפליקציה**
```bash
cp .env.example .env         # ממלאים URL ו-anon key מ-Settings → API
npm run dev
```
פותחים את http://localhost:5173, נכנסים עם המשתמש ומעלים את קובצי הדוגמאות.

> בפעם הראשונה Tesseract מוריד את קובצי השפה (עברית ואנגלית, כ-15MB), ולכן העמוד הראשון איטי יותר.

## בדיקות

```bash
npm test                     # בדיקות יחידה למנוע: נרמול, ת.ז., תאריכים, עיגון, פענוח, בניית טופס
```

## מדידת דיוק

1. ממלאים את `eval/truth.json` עם 10–15 טפסים (מבנה כמו ב-`eval/truth.example.json`). הערכים המסומנים בצהוב בטפסי הדוגמה הם טבלת האמת. כדאי לכלול גם 2–3 צילומי טלפון.
2. במסך הבדיקה: ייצוא → JSON.
3. מריצים:
```bash
node eval/run.mjs eval/truth.json ~/Downloads/התחייבויות_YYYY-MM-DD.json
```
הפלט: אחוז דיוק לכל שדה ולכל גורם שולח, ורשימת השגיאות.

## מבנה הנתונים

| טבלה | תוכן |
|---|---|
| `batches` | קובץ שהועלה |
| `pages` | עמוד: נתיב תמונה, טקסט OCR, מיקומי מילים, סטטוס, זמן עיבוד |
| `forms` | טופס: פרטי מטופל ודגימה, `field_meta` (ביטחון, ציטוט, סימון, סיבות), אזהרות |
| `records` | שורה לכל מספר התחייבות, סטטוס pending/approved |
| `records_flat` | view: שורה מלאה לכל התחייבות (מה שמיוצא) |
| `senders` | הרשימה הסגורה של גורמים שולחים |

## מגבלות ידועות
- כתב יד: Tesseract מזהה אותו חלש, ולכן שדות בכתב יד נשענים על המודל ומסומנים לרוב כ"לא אומת מול טקסט הדף". במקרה כזה החיתוך המרחף מציג את העמוד המלא.
- רשימת הגורמים השולחים היא בסיסית, ויש להשלים אותה מול רשימת המוסדות של משרד הבריאות.
- זיהוי טופס שמשתרע על כמה עמודים מבוסס על סימון "המשך" מהמודל. כדאי לבדוק אותו על טפסי SAP.

## מה נדרש להטמעה במעבדה
- API שמעביר רשומות מאושרות למערכת המעבדה. פורמט ייצוא ה-JSON כבר בנוי במבנה הזה.
- משתמשים והרשאות לפי תפקיד, ומדיניות שמירת נתונים מוסכמת (כמה ימים נשמרים מקורות).
- הרצת המודל בסביבה מאושרת למידע רפואי.
